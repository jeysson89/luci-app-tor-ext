# luci-app-tor-ext

Расширенное приложение LuCI для управления установленным **Tor** на OpenWrt 25.12
(rpcd/ucode, без CBI). Интерфейс на русском языке.

## Возможности

| Раздел | Что делает |
|--------|------------|
| **Статус** | Состояние сервиса, bootstrap, версия, аптайм, цепочки, выходной узел, график скорости с подсветкой пика и таблица статистики, проверка внешнего IP (действительно ли трафик идёт через Tor) |
| **Мосты** | Отдельный раздел на каждый тип транспорта (obfs4, snowflake, meek_lite, webtunnel, обычный мост). Кнопка «+» добавляет мост, «Проверить» запускает изолированную проверку только этого моста, «Проверить все мосты» — проверку всех сразу |
| **Конфигурация** | Полный редактор `/etc/tor/torrc`: проверка через `tor --verify-config`, автоматические резервные копии (последние 20) и восстановление |
| **Порты и сервисы** | SocksPort / TransPort / DNSPort / ControlPort, скрытые сервисы `.onion` (добавление, адрес, копирование, удаление) |
| **Проксирование** | Прозрачное проксирование через отдельную таблицу nftables `inet tor_ext`: выбор клиентов (в том числе из аренд DHCP), перенаправление DNS/TCP в Tor, kill switch, блокировка IPv6/QUIC/DoT, предпросмотр правил и счётчики |
| **Трафик** | Мониторинг соединений клиентов (таблица conntrack) с фильтром по устройству и тексту, агрегацией по ресурсу, объёмом трафика и возможностью закрыть соединение или все соединения устройства |
| **Логи** | Журнал Tor, системный журнал и журнал приложения, автообновление, выгрузка в файл |
| **Мониторинг** | Сторожевой таймер (cron, авторестарт) и уведомления (Telegram или произвольный webhook) |

## Установка

### Готовый пакет

Скачать: [luci-app-tor-ext-1.0.0-r1.apk](https://github.com/jeysson89/luci-app-tor-ext/releases/download/v1.0.0/luci-app-tor-ext-1.0.0-r1.apk)

```sh
scp luci-app-tor-ext-1.0.0-r1.apk root@<роутер>:/tmp/
apk add --allow-untrusted /tmp/luci-app-tor-ext-1.0.0-r1.apk
```

Пакет не подписан, поэтому используется `--allow-untrusted`. После установки:

* перезапускается `rpcd` (новый ubus-объект `tor-ext`),
* выполняется миграция старой ручной настройки Tor (см. ниже),
* включается сервис `tor-ext`, который применяет правила прозрачного проксирования.

### Сборка из исходников (OpenWrt SDK)

В каталоге есть `Makefile` для штатной сборки в SDK OpenWrt 25.12:

```sh
make package/luci-app-tor-ext/compile V=s
```

### Сборка .apk без SDK (на самом роутере)

Для роутеров, где нет SDK, пакет собирается статическим `apk` Alpine 3.0.8,
который умеет `apk mkpkg`:

```sh
# 1. статический apk Alpine (aarch64)
curl -o /tmp/apk-tools-static.apk \
  https://dl-cdn.alpinelinux.org/alpine/latest-stable/main/aarch64/apk-tools-static-3.0.8-r0.apk
apk extract --allow-untrusted --destination /tmp/apkstatic /tmp/apk-tools-static.apk

# 2. сборка
sh dev/build-apk.sh /tmp/pkgroot /tmp/luci-app-tor-ext-1.0.0-r1.apk
```

## Зависимости

* `tor` — обязателен;
* `lyrebird` (или `obfs4proxy` / `snowflake-client`) — транспорты, см. ниже;
* `conntrack` — для закрытия соединений в разделе «Трафик» (`apk add conntrack`);
* `curl`, `nftables`, `luci-base`, `rpcd-mod-ucode`.

Пакет `luci-app-tor-ext` требует только `tor`, `curl` и `nftables`: транспорты
подключаются опционально, поэтому лишние мегабайты на флеш-памяти не расходуются.

## Как это устроено

```
/usr/share/rpcd/ucode/tor-ext      бэкенд (ucode), объект ubus "tor-ext"
/usr/libexec/tor-ext/ctl           клиент control-порта Tor (cookie auth)
/usr/libexec/tor-ext/apply-proxy   генерация и загрузка правил nftables
/usr/libexec/tor-ext/test-bridges  изолированный тест мостов
/usr/libexec/tor-ext/watchdog      сторожевой таймер (cron)
/usr/libexec/tor-ext/notify        отправка уведомлений (Telegram/webhook)
/usr/libexec/tor-ext/migrate       миграция со старой ручной настройки
/etc/config/tor_ext                настройки проксирования, watchdog, уведомлений
/etc/init.d/tor-ext                применение правил при загрузке
```

`/etc/tor/torrc` — единственный источник настроек Tor. Приложение его читает,
правит (с резервной копией и проверкой `tor --verify-config`) и перезапускает Tor.

## Прозрачное проксирование

Правила живут в отдельной таблице `inet tor_ext` и не конфликтуют с `fw4`:

1. `tcp dport {22, 9040, 9050, 9051, 9053} return` — не проксируем сами порты Tor;
2. DNS (udp/tcp 53) → `redirect to :9053` (DNSPort Tor) — **правило стоит перед**
   исключением частных сетей, иначе клиенты продолжали бы использовать локальный
   резолвер (dnsmasq/sing-box fake-ip) и получали нерабочие адреса;
3. частные сети (LAN, 192.168.0.0/16 и т. п.) — без проксирования;
4. DoT (853) — отклоняется, чтобы клиент не утекал мимо Tor;
5. весь остальной TCP → `redirect to :9040` (TransPort);
6. в цепочке forward — kill switch (весь трафик клиента, который не был
   перенаправлен, отбрасывается) и блокировка IPv6 для LAN.

IPv6 блокируется с ICMPv6-ответом (`reject`), чтобы клиент сразу переключился
на IPv4, а не ждал таймаута.

> **Важно:** если на роутере уже работает другой прозрачный прокси
> (Forkop/podkop, sing-box), устройство не должно быть в списках обоих
> одновременно. Уберите его из «полностью маршрутизируемых» адресов
> другого приложения, иначе DNS будет отдавать fake-ip-адреса, которые Tor
> не может использовать.

## Мосты и транспорты

Типы мостов разнесены по разделам, каждый со своим списком:

| Тип | Транспорт | Бинарник |
|-----|-----------|----------|
| obfs4 | obfs4 | `lyrebird` или `obfs4proxy` |
| snowflake | snowflake | `lyrebird` или `snowflake-client` |
| meek_lite | meek_lite | `lyrebird`, `meek-client` или `obfs4proxy` |
| webtunnel | webtunnel | `lyrebird` или `webtunnel-client` |

Современный Tor Browser (15+) использует **lyrebird** — один бинарник на все
транспорты. В фидах OpenWrt его нет, но он есть в community-репозитории Alpine
(статическая сборка, работает на OpenWrt):

```sh
# на роутере (нужно ~17 МБ свободного места)
curl -o /tmp/lyrebird.apk \
  https://dl-cdn.alpinelinux.org/alpine/latest-stable/community/aarch64/lyrebird-0.8.1-r7.apk
mkdir -p /tmp/lyre
apk extract --allow-untrusted --destination /tmp/lyre /tmp/lyrebird.apk
cp /tmp/lyre/usr/bin/lyrebird /usr/bin/lyrebird && chmod 0755 /usr/bin/lyrebird
rm -rf /tmp/lyre /tmp/lyrebird.apk
```

После этого приложение само выбирает lyrebird и пишет в `torrc` одну строку
для всех транспортов:

```
ClientTransportPlugin meek_lite,obfs2,obfs3,obfs4,scramblesuit,webtunnel,snowflake exec /usr/bin/lyrebird
```

Встроенные мосты Tor Browser (obfs4/snowflake/meek_lite) берутся из
`pt_config.json` в исходниках Tor Browser.

Проверка моста запускает отдельный экземпляр Tor с одним мостом и отдельным
DataDirectory: основной Tor это не затрагивает. Показываются процент
bootstrap, состояние guard-соединений и вывод транспорта (в том числе
`lyrebird.log`).

### Как раздел «Мосты» работает с /etc/tor/torrc

`/etc/tor/torrc` — единственный источник истины, раздел «Мосты» — его
редактор для строк `Bridge`:

| Действие в разделе «Мосты» | Что происходит с torrc |
|---------------------------|-------------------------|
| Открытие страницы         | строки `Bridge` читаются из файла и раскладываются по разделам транспортов (адрес, отпечаток, параметры) |
| «+» / «Удалить»           | меняется только список в интерфейсе, файл не трогается |
| «Сохранить»               | **все** строки `Bridge` перезаписываются списком из интерфейса, строки `ClientTransportPlugin` заменяются на выбранный транспорт, `UseBridges` выставляется по наличию мостов, затем делается резервная копия, проверка `tor --verify-config` и перезапуск Tor |
| «Обновить из файла»       | список перечитывается из torrc (в том числе мосты, добавленные вручную) |
| «Проверить»                | файл не меняется: поднимается отдельный экземпляр Tor с одним мостом |

Если torrc правили вручную (например, добавили мост в редакторе), то при
нажатии «Сохранить» приложение **не станет молча затирать правку**: файл
снабжён отпечатком (mtime+размер), и если он изменился после загрузки
страницы, сохранение вернёт конфликт и предложит подтвердить перезапись.

Полезно знать:

* комментарии и остальные директивы torrc при сохранении сохраняются —
  перезаписываются только `Bridge`, `ClientTransportPlugin` и `UseBridges`;
* перед каждой записью создаётся резервная копия в `/etc/tor/backups`
  (восстановить можно в разделе «Конфигурация»);
* если указать другой тип моста (например, только snowflake), строки
  `ClientTransportPlugin` будут приведены в соответствие с выбранным
  транспортом, а `Bridge`-строки других типов удалены — то есть список
  мостов в интерфейсе всегда полностью определяет содержимое файла.

### Что работает на конкретном роутере

| Транспорт | Результат проверки |
|------------|--------------------|
| obfs4 | работает (bootstrap 100 % за ~10 с) |
| snowflake | транспорт запускается, но TLS-рукопожатие с брокером обрывается — фронтинг блокируется сетью |
| meek_lite | аналогично: соединение не устанавливается |
| webtunnel | встроенные мосты только IPv6, у роутера нет IPv6 |

Вывод транспорта показывается в разделе «Мосты» (кнопка «Проверить» → блок
«Результат проверки»), поэтому причину неудачи видно сразу.

